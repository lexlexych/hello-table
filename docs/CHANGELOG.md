## 18.08.2026 — Self-hosted n8n и workflow поиска и бронирования столика

**Что сделано:** n8n 2.33.3 добавлен в локальный и production Docker Compose. Созданы
два неактивных экспортируемых workflow: поиск свободных столиков и атомарная бронь
выбранного столика. Оба сначала проверяют HMAC исходного тела, затем валидируют вход,
вызывают разрешённую Postgres-функцию параметризованным запросом и возвращают ответ по
существующему контракту агента.

**Изменено:** созданы `n8n/workflows/reservation-check.json`,
`n8n/workflows/reservation-create.json` и `n8n/README.md`. В
`deploy/docker-compose.dev.yml` добавлен локальный n8n на `127.0.0.1:5678`, в
`deploy/docker-compose.yml` — внутренний production-сервис без опубликованного порта;
для каждого используется отдельный named volume и лимит памяти 1 ГБ. Добавлены команды
`pnpm n8n:{up,down,logs}`, `N8N_ENCRYPTION_KEY` в `.env.example`, отключено сохранение
execution payload и непроверенные community packages. Локальный Postgres также привязан
к loopback.

**Документация:** `docs/PROJECT.md` приведён к self-hosted схеме «локальный Docker или
Hetzner Docker», зафиксированы версия, текущий статус workflow и частичный статус
итерации 5. В `docs/architecture.md` записаны решения о размещении, SQLite volume,
privacy-настройках и Crypto credential. В `docs/tool-contracts.md` обновлён статус
реализации, в `docs/manual-tests.md` добавлена ручная проверка полного сценария.

**Тесты:** по указанию владельца новые тестовые файлы не создавались. Существующие
проверки прошли: `pnpm lint`; `pnpm typecheck`; `pnpm test` — 35 файлов, 305 тестов;
`docker compose ... config --quiet` для dev и production. Оба JSON импортированы командой
n8n CLI в чистый временный volume (`Successfully imported 2 workflows`), финальный
локальный контейнер достиг состояния `healthy`; его временные контейнер, volumes и сеть
удалены после проверки.

**Ручные проверки:** `docs/manual-tests.md`, раздел «3. Локальные workflow поиска и
бронирования в n8n» — после создания credentials, импорта и активации владельцем.

**Итерация:** §12, итерация 5 переведена в `[~]`: два workflow бронирования и базовая
self-hosted конфигурация готовы; остальные workflow, Caddy и фактический деплой остаются.

## 18.08.2026 — Демо-кейс «Базилик»: seed из меню, правила ресторана в промпте, три инструмента агента

workflow ещё нет (итерация 5), поэтому вызовы отрабатывают как недоступность вебхука.

произносится до сетевого вызова, доменный код ошибки превращается в немецкую фразу,
ответ не по контракту даёт `invalid_response`, молчащий сервер — `timeout`. Скрипт
проверки одноразовый и в репозиторий не добавлен; тесты остаются долгом итерации 6.

**Ручные проверки:** `docs/manual-tests.md`, разделы «1. Демо-данные „Базилик“ в базе и в
портале» и «2. Разговор с инструментами при неподнятом n8n».

**Итерация:** §12 итерации 2 (дополнена), 6 и 8 (`[~]`, частично). Порядок «итерация 5
предшествует итерации 6» нарушен по прямому указанию владельца ради демо-кейса;
обоснование и цена решения — в `docs/architecture.md`.

⚠️ Владельцу: перед следующим `pnpm agent:dev` нужно дописать в свой `.env` три значения —
`RESTAURANT_ID`, `N8N_BASE_URL` и `N8N_WEBHOOK_SECRET` (не короче 32 символов). Без них
конфиг не проходит валидацию и воркер не стартует.
