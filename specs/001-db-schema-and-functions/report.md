# Отчёт реализации спеки 001

## Реализовано

- Четыре обратимые dbmate-совместимые миграции: расширения, ресторан/расписание, меню и
  операционные таблицы.
- Восемь публичных RPC из спецификации, вспомогательные функции окон/слотов/нормализации,
  триггеры ретенции и атомарные блокировки брони и самовывоза.
- Идемпотентные роли и минимальные права: `n8n_app` не имеет прав на таблицы; `portal_app`
  не имеет `DELETE`; `PUBLIC` не исполняет функции.
- TypeScript-раннер с advisory lock, SHA-256 применённых файлов, откатом одной миграции,
  безопасным локальным reset и проверкой паролей ролей.
- Идемпотентный трёхъязычный seed, Compose PostgreSQL, конфигурация pnpm/Vitest/Biome/TS,
  документация SQLSTATE и ручных проверок.
- Локальные Vitest-проверки каркаса миграций, состава схемы, функций и запрета чтения под
  `n8n_app`; global setup удаляет API-секреты и пересоздаёт только `restaurant_test`.

## Отклонения и ограничения окружения

Полный обязательный прогон и генерация lock-файла невозможны в предоставленном контейнере:
Docker отсутствует, Node.js имеет версию 20.20.2 вместо требуемой 24, а npm registry отвечает
403 при `pnpm install`. Внешних вызовов приложения, API-ключей или LLM не выполнялось.
Поэтому точная runtime-проверка PostgreSQL image и SQL остаётся обязательной до приёмки.
Автотесты из подробной матрицы спецификации (включая детерминированные и стрессовые гонки)
должны быть дополнены и выполнены в пригодном окружении; текущий результат нельзя считать
готовой приёмкой.

## Команды и результаты

- `node -v` → `v20.20.2` (ограничение окружения).
- `pnpm -v` → `10.28.1`.
- `docker --version` → exit 127, `docker: command not found`.
- `pnpm install --ignore-scripts` → exit 1, `ERR_PNPM_FETCH_403` для registry.npmjs.org.
- `pnpm lint`, `pnpm typecheck`, `pnpm test` не запускались: зависимости не установлены;
  запуск тестов без PostgreSQL также невозможен.

## Запуск в поддерживаемом окружении

```sh
pnpm install --frozen-lockfile
pnpm db:up
DATABASE_URL=postgres://app_owner:app_owner@127.0.0.1:5432/restaurant pnpm db:migrate
DATABASE_URL=postgres://app_owner:app_owner@127.0.0.1:5432/restaurant pnpm db:seed
pnpm lint
pnpm typecheck
pnpm test
```

## Исправления после code review

- Миграция и откат теперь проверяют, что соединение выполняется именно ролью `app_owner`
  и что эта роль владеет базой; оба пути сериализованы одним advisory lock.
- Перед откатом снимаются определения проектных функций, чтобы зависимости `%ROWTYPE` и
  триггеров не блокировали откат таблиц. Полный набор функций снова ставится следующим
  `db:migrate`; откат больше не пытается создать функции поверх уже удалённых таблиц.
- Если пароль прикладной роли пропущен, раннер явно переводит её в `NOLOGIN`; корректный
  пароль одновременно возвращает `LOGIN`. Это исключает сохранение старого доступа.
- Ветка автоматического выбора pickup-слота повторно проверяет вместимость под блокировкой;
  malformed JSON получает документированный SQLSTATE вместо внутренних ошибок cast.
- Dev volume PostgreSQL 18 использует новый mount point `/var/lib/postgresql`.
- Повторные попытки `pnpm install --offline` и `pnpm install --lockfile-only` не создали
  lock-файл: в cache нет metadata, а registry отвечает 403. Integrity metadata вручную не
  создавалась.
