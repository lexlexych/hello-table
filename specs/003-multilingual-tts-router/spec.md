# Спецификация 003 — Мультиязычность

## 1. Цель и контекст

Итерация 4 из docs/PROJECT.md §12: «Мультиязычность: определение языка, TTS-роутер с
реализациями voxtral + elevenlabs, i18n-ресурсы, форматирование дат и цен. Piper НЕ
поднимаем — он в итерации 14».

Прототип итерации 3 говорит на одном языке. Здесь он учится трём: определять язык по
первой реплике, переключаться в середине разговора, синтезировать речь разным движком
на разный язык и произносить числа, даты и цены по правилам каждого языка.

Разделы PROJECT.md: **§4** целиком (определение и переключение языка, языковые ресурсы,
форматирование), **§2.2** (маршрутизация TTS по языку, роутер за единым интерфейсом),
§1.2 сценарий C (самовывоз на русском с автоматическим переключением), §5.1
(`enabled_languages`, `default_language` ресторана), §14 (краткость реплик).

Профильный навык — `.claude/skills/voice-testing/SKILL.md`: чек-лист по каждому языку.
Из сценариев A–F здесь проверяются только те, что не требуют инструментов: приветствие,
переключение языка в середине разговора, произнесение чисел и цен.

### 1.1 Предусловия

- **Спека 002 должна быть реализована и принята.** Эта спека переиспользует её каркас:
  `agent/src/config.ts`, `session.ts`, `telemetry.ts`, `i18n/de.yaml`,
  `prompts/system.de.md`, тесты на `voice.testing`. На момент написания `/impl 002`
  выполняется, `agent/package.json` уже создан с нужными зависимостями.
- **Два входных значения из итерации 3 отсутствуют** и меняют часть решений:
  1. измеренный бюджет задержки (§3.3 подлежит пересчёту);
  2. ответ на вопрос, есть ли у Voxtral TTS немецкий голос.

  Спека написана так, чтобы **быть корректной при любом ответе**: выбор движка на каждый
  язык — это конфигурация (`TTS_PROVIDER_<lang>`), а не код. Если немецкого голоса у
  Voxtral нет, меняется только значение переменной окружения. См. раздел 7.

## 2. Объём

**Входит:**

1. `LanguageTracker` — определение и переключение языка сессии по правилам §4.1,
   с учётом `enabled_languages` ресторана.
2. **TTS-роутер** за единым интерфейсом с двумя взаимозаменяемыми реализациями
   (`voxtral`, `elevenlabs`), выбираемыми через конфиг. Включая решение двух реальных
   проблем совместимости: разная частота дискретизации и разная способность к стримингу.
3. Языковые ресурсы `ru.yaml`, `en.yaml` и системные промпты `system.ru.md`,
   `system.en.md`.
4. `formatting.ts` — время, дата, цена и число гостей по правилам каждого языка (§4.2).
5. Подключение всего этого к сессии: смена языка меняет голос, промпт и набор фраз.
6. Автотесты: `LanguageTracker`, форматирование и роутер — чистая логика, проверяется
   полностью локально без ключей и сети.

**Не входит (явно):**

- **Piper** — итерация 14. Третья реализация роутера здесь не создаётся: заглушек не
  делаем (AGENTS.md §6), интерфейс уже позволяет добавить её одним файлом;
- инструменты агента, n8n, база — итерации 5–8. Агент по-прежнему ничего не бронирует,
  и `formatting.ts` пока применяется только к фразам из i18n;
- перевод названий блюд — они уже лежат в базе тремя колонками (§4.2), но читать их
  некому до итерации 6;
- язык уведомления в Telegram (§4.1 пункт 5) — итерация 8;
- смена языка приветствия по данным ресторана из БД — агент к базе не ходит (§3.5),
  значения `default_language` и `enabled_languages` приходят из конфига до итерации 5.

### 3.2 Определение и переключение языка — `agent/src/language.ts`

Правила §4.1 в коде. Фреймворк отдаёт распознанный язык готовым: событие
`UserInputTranscribedEvent` содержит поле `language: LanguageCode | null` (проверено в
`@livekit/agents` 1.6.4). Своё определение языка писать не нужно — это подтверждено
проверкой Voxtral в итерации 3.

```ts
export const LANGUAGES = ['de', 'ru', 'en'] as const;
export type Lang = (typeof LANGUAGES)[number];

export function isLang(value: string | null | undefined): value is Lang;

/** Приводит код фреймворка ('de-DE', 'ru', 'en-GB') к нашему языку или null. */
export function toLang(code: string | null | undefined): Lang | null;

export interface LanguageTrackerOptions {
  /** Стартовый язык ресторана (§4.1 п.1). */
  initial: Lang;
  /** Языки, включённые у ресторана (§5.1 enabled_languages). */
  enabled: readonly Lang[];
  /** Сколько подряд идущих финальных реплик на другом языке нужно для переключения. */
  switchAfter: number;
}

export interface ObserveResult {
  language: Lang;
  changed: boolean;
}

export class LanguageTracker {
  constructor(options: LanguageTrackerOptions);
  get current(): Lang;
  /** Скармливать ТОЛЬКО финальные транскрипты (isFinal === true). */
  observe(detected: string | null): ObserveResult;
  reset(): void;
}
```

Поведение, точно:

| Ситуация | Что делает |
|---|---|
| Первая финальная реплика, язык распознан и включён у ресторана | Немедленно фиксирует его как язык сессии (§4.1 п.3), даже если он отличается от стартового. Счётчик обнуляется |
| Распознанный язык совпадает с текущим | Счётчик обнуляется, язык не меняется |
| Распознанный язык включён и отличается от текущего | Счётчик +1. При достижении `switchAfter` — переключение, счётчик обнуляется |
| Язык не распознан (`null`) | Игнорируется целиком: счётчик **не** сбрасывается. Пауза или неразборчивая реплика не должна ломать серию |
| Язык распознан, но **не входит** в `enabled` | Обрабатывается как «не распознан». Ресторан без русского не должен уезжать на русский |
| Язык вне набора de/ru/en (например `fr`) | То же самое — игнорируется |

Конструктор падает, если `initial` отсутствует в `enabled`, — это ошибка конфигурации,
и она должна вскрыться при старте, а не в разговоре (§0.4).

⚠️ **Порог переключения.** PROJECT.md §4.1 п.4 говорит: «При смене языка более чем на
две реплики подряд — переключиться. Не переключаться от одного иностранного слова».
Формулировка допускает два прочтения — «после двух» и «после трёх». Смысл однозначен
только в отрицательной части: не реагировать на одно слово. Реализуем **порог по
умолчанию 2** и выносим его в конфиг `AGENT_LANGUAGE_SWITCH_AFTER`, потому что три
реплики на чужом языке — это заметно долгий отрезок разговора, в котором агент отвечает
не на том языке. Значение проверяется владельцем вживую и уточняется в PROJECT.md по
итогам (см. открытый вопрос 1).

### 3.3 TTS-роутер — `agent/src/tts/`

§2.2 требует: «роутер за единым интерфейсом с тремя взаимозаменяемыми реализациями,
выбираемыми через конфиг `TTS_PROVIDER_<lang>`. Не ветвись по `if` в коде сессии».

Интерфейс, который надо реализовать (сверено с `@livekit/agents` 1.6.4):

```ts
abstract class TTS {
  constructor(sampleRate: number, numChannels: number, capabilities: TTSCapabilities);
  abstract label: string;
  abstract synthesize(text: string, connOptions?: APIConnectOptions,
                      abortSignal?: AbortSignal): ChunkedStream;
  abstract stream(options?: { connOptions?: APIConnectOptions }): SynthesizeStream;
  close(): Promise<void>;
}
interface TTSCapabilities { streaming: boolean; alignedTranscript?: boolean }
```

#### 3.3.1 Две реальные несовместимости реализаций

Обе выяснены разбором установленных пакетов, обе обязаны быть решены в роутере.

| | Voxtral (`agents-plugin-mistralai`) | ElevenLabs (`agents-plugin-elevenlabs`) |
|---|---|---|
| Частота | **24000 Гц**, жёстко зашита константой | из `encoding`; PCM только `pcm_16000`, `pcm_22050` (по умолчанию), `pcm_44100` |
| Стриминг | `{ streaming: false }` | `{ streaming: true }`, WebSocket |
| Язык | параметра языка нет вообще | есть `language` / `languageCode` |
| Голос | `voice` из закрытого списка либо `refAudio` | `voiceId` |

**Проблема 1 — общей частоты не существует.** `sampleRate` фиксируется в конструкторе
`TTS`, и фреймворк по нему настраивает источник звука. У Voxtral 24000, а у ElevenLabs
такого варианта нет вовсе. Целевая конфигурация §2.2 (de/en → Voxtral, ru → ElevenLabs)
без пересемплирования нереализуема.

Решение: роутер объявляет **одну** частоту (`TTS_SAMPLE_RATE`, по умолчанию 24000) и
оборачивает любую реализацию с другой частотой декоратором `ResamplingTts` на
`AudioResampler` из `@livekit/rtc-node` (нативный, на Sox; конструктор
`(inputRate, outputRate, channels, quality)`, метод `push(frame)`, обязательный
`close()` — иначе течёт файловый дескриптор).

Почему 24000 по умолчанию: это натив Voxtral, то есть в целевой конфигурации основной
языковой поток идёт без пересемплирования, а ElevenLabs (`pcm_44100`) понижается —
понижение чище повышения. На фазе разработки, когда все три языка на ElevenLabs, можно
поставить `TTS_SAMPLE_RATE=22050` и не пересемплировать вообще. Всё равно на телефонии
звук в итоге уходит в 8 кГц G.711, так что разница в качестве выше 16 кГц практического
значения не имеет.

**Проблема 2 — Voxtral не стримит.** Роутер объявляет `streaming: true` и приводит
нестримящие реализации к стриминговым штатным средством фреймворка:
`new tts.StreamAdapter(inner, sentenceTokenizer)` — он режет текст по предложениям и
синтезирует их по очереди. Токенизатор берётся из `tokenize.basic`.

Порядок обёрток фиксированный: `StreamAdapter(ResamplingTts(provider))`. Ресемплер
внутри, потому что он должен видеть кадры провайдера; адаптер снаружи, потому что он
превращает `synthesize()` в поток.

#### 3.3.2 Контракты

```ts
// agent/src/tts/types.ts
export type TtsProviderName = 'voxtral' | 'elevenlabs';

export interface TtsProviderConfig {
  provider: TtsProviderName;
  /** Голос конкретного движка: voiceId у ElevenLabs, voice у Voxtral. */
  voice: string;
}

/** Фабрика создаёт «сырую» реализацию; нормализацией занимается роутер. */
export type TtsFactory = (lang: Lang, config: TtsProviderConfig) => TTS;
```

```ts
// agent/src/tts/resample.ts
/**
 * Декоратор: приводит выход любой TTS к нужной частоте.
 * Прозрачен, если частоты уже совпадают, — тогда создавать его не нужно.
 */
export class ResamplingTts extends TTS {
  label: string;                       // `resample(${inner.label})`
  constructor(inner: TTS, targetSampleRate: number);
  synthesize(text, connOptions?, abortSignal?): ChunkedStream;
  stream(options?): SynthesizeStream;
  close(): Promise<void>;              // обязан закрыть inner И освободить реземплеры
}
```

```ts
// agent/src/tts/router.ts
export interface TtsRouterOptions {
  /** По одной реализации на каждый включённый язык. */
  providers: Readonly<Record<Lang, TTS>>;
  /** Откуда роутер узнаёт текущий язык. Читается в момент начала синтеза. */
  getLanguage: () => Lang;
  sampleRate: number;
  sentenceTokenizer: SentenceTokenizer;
}

export class TtsRouter extends TTS {
  label = 'restaurant.tts-router';
  constructor(options: TtsRouterOptions);
  /** Нормализованная реализация текущего языка — для тестов и телеметрии. */
  currentProviderLabel(): string;
  synthesize(text, connOptions?, abortSignal?): ChunkedStream;
  stream(options?): SynthesizeStream;
  close(): Promise<void>;              // закрывает все реализации
}
```

Внутри конструктора для каждого языка:

1. если `provider.sampleRate !== sampleRate` → обернуть в `ResamplingTts`;
2. если `provider.capabilities.streaming === false` → обернуть в `StreamAdapter`;
3. сохранить в карту `Record<Lang, TTS>`.

`super(sampleRate, 1, { streaming: true })`.

Язык читается **в момент вызова** `stream()` / `synthesize()`, то есть на границе реплики.
Переключение посреди уже начатой фразы не происходит и не нужно: реплика договаривается
тем голосом, которым начата.

#### 3.3.3 Фабрики

```ts
// agent/src/tts/voxtral.ts
export function createVoxtralTts(config: { apiKey: string; model: string; voice: string }): TTS;
```
Проверка при старте: `voxtral` для русского запрещён — Voxtral TTS русский не
поддерживает (§2.2). Конфигурация `TTS_PROVIDER_RU=voxtral` обязана падать при старте с
внятным сообщением, а не выясняться в разговоре.

```ts

export function createElevenLabsTts(config: {
  apiKey: string; model: string; voiceId: string; lang: Lang;

```
`language` передаётся в плагин — он использует его для нормализации текста под язык.

### 3.4 Форматирование — `agent/src/formatting.ts`

§4.2: «Числа, даты и время произносятся по-разному в трёх языках. Не отдавай
форматирование LLM. Реализуй `format_time(dt, lang)` и `format_price(cents, lang)` и
подставляй готовые строки в контекст».

```ts
export function formatTime(at: Date, lang: Lang, timezone: string): string;
export function formatDate(at: Date, lang: Lang, timezone: string): string;
export function formatDateTime(at: Date, lang: Lang, timezone: string): string;
export function formatPrice(cents: number, lang: Lang): string;
/** «4 человека» / «vier Personen» — с русской плюрализацией. */
export function formatPartySize(count: number, lang: Lang): string;
```

Реализация на `Intl`, локали: `de` → `de-DE`, `ru` → `ru-RU`, `en` → `en-GB`
(Европа и евро; для `en-US` символ валюты встал бы неверно относительно суммы).

Ожидаемый вид (закрепляется тестами):

| | de | ru | en |
|---|---|---|---|
| время 19:30 | `19:30` | `19:30` | `7:30 pm` |
| цена 950 | `9,50 €` | `9,50 €` | `€9.50` |
| 1 гость | `eine Person` | `1 гость` | `1 guest` |
| 2 гостя | `zwei Personen` | `2 гостя` | `2 guests` |
| 5 гостей | `fünf Personen` | `5 гостей` | `5 guests` |

Русская плюрализация — через `Intl.PluralRules('ru-RU')`, категории `one / few / many`
(«гость / гостя / гостей»). Это классическая ловушка: наивное `n === 1 ? 'гость' :
'гостей'` даёт «2 гостей». Числительные до двенадцати на немецком пишутся словами —
так естественнее звучит в синтезе; выше — цифрами.

⚠️ Всё это требует полного ICU. Node 24 собирается с full-icu по умолчанию, но тест
обязан это проверить: при small-icu `Intl` молча отдаст английский формат для `ru-RU`,
и агент начнёт называть цены не по-русски. Проверяется утверждением на неASCII-вывод.

### 3.5 Языковые ресурсы и промпты

`agent/src/i18n/{ru,en}.yaml` — те же ключи, что в `de.yaml` из спеки 002
(`greeting`, `ai_disclosure`, `goodbye`, `error_unavailable`). Набор ключей обязан
совпадать во всех трёх файлах — это проверяется тестом, иначе при переключении языка
агент упрётся в отсутствующую фразу посреди разговора.

⚠️ **Объявление об ИИ на русском и английском пишет владелец.** Это текст с правовым
значением (§11.1), выдумывать его нельзя. В файлах остаётся заготовка с пометкой; тест
проверяет непустоту и отсутствие `TODO`, то есть до заполнения владельцем сборка красная.
Так и задумано.

`agent/src/prompts/system.{ru,en}.md` — переводы `system.de.md` с теми же
ограничениями: одна–две фразы, ничего не выдумывать, не менять язык самому.

⚠️ Промпт **не** должен содержать инструкции «отвечай на языке клиента»: язык
определяется трекером и задаётся кодом. Модель, которой разрешено выбирать язык самой,
начнёт это делать невпопад, а голос TTS за ней не последует.

### 3.6 Подключение к сессии — изменения в `session.ts` и `index.ts`

1. Создать `LanguageTracker` из конфига.
2. Собрать `TtsRouter` и передать его в `AgentSession` вместо одиночного TTS.
   В коде сессии **нет ни одного `if` по языку** — этого требует §2.2.
3. Подписаться на `UserInputTranscribed`; для событий с `isFinal === true` вызывать
   `tracker.observe(event.language)`.
4. При `changed === true`:
   - обновить инструкции агента: `await agent.updateInstructions(promptFor(lang))`
     (метод есть в `voice.Agent` 1.6.4);
   - переключить набор фраз i18n на новый язык;
   - записать факт переключения в телеметрию **как код языка, без текста реплики** —
     логировать транскрипты запрещено (§0.4).
   Голос TTS менять отдельно не нужно: роутер прочитает язык на следующей реплике сам.
5. Приветствие и объявление об ИИ произносятся на стартовом языке (§4.1 п.2) — логика
   из спеки 002 сохраняется, меняется только источник языка.

### 3.7 Конфигурация — изменения в `config.ts` и `.env.example`

Добавляется (часть переменных `/impl 002` уже завёл в `.env.example`):

```
AGENT_DEFAULT_LANGUAGE=de               # §5.1 default_language
AGENT_ENABLED_LANGUAGES=de,ru,en        # §5.1 enabled_languages
AGENT_LANGUAGE_SWITCH_AFTER=2           # порог переключения, см. 3.2

TTS_PROVIDER_DE=elevenlabs              # voxtral | elevenlabs
TTS_PROVIDER_RU=elevenlabs              # voxtral запрещён: русского голоса нет
TTS_PROVIDER_EN=elevenlabs
TTS_SAMPLE_RATE=24000                   # единая частота выхода роутера

ELEVENLABS_VOICE_ID_DE=
ELEVENLABS_VOICE_ID_RU=
ELEVENLABS_VOICE_ID_EN=
ELEVENLABS_ENCODING=pcm_22050           # pcm_16000 | pcm_22050 | pcm_44100

VOXTRAL_VOICE_DE=                       # заполняется, только если TTS_PROVIDER_DE=voxtral
VOXTRAL_VOICE_EN=
```

Правила валидации zod, все — падение при старте (§0.4):

- `AGENT_DEFAULT_LANGUAGE` входит в `AGENT_ENABLED_LANGUAGES`;
- `AGENT_ENABLED_LANGUAGES` непустой и состоит только из `de|ru|en`;
- для каждого **включённого** языка задан провайдер и непустой голос под этот провайдер;
- `TTS_PROVIDER_RU !== 'voxtral'`;
- `TTS_SAMPLE_RATE` — одно из 16000, 22050, 24000, 44100;
- `AGENT_LANGUAGE_SWITCH_AFTER` — целое 1..5.

Переменная `AGENT_LANGUAGE` из спеки 002 (жёсткое `de`) **удаляется** — её заменяют
`AGENT_DEFAULT_LANGUAGE` и `AGENT_ENABLED_LANGUAGES`.

## 5. Тестирование

### 5.1 Автотесты (vitest, только локальное окружение)

Итерация удобна тем, что почти вся её логика — чистая и проверяется полностью:
переключение языка, форматирование и маршрутизация не требуют ни ключей, ни сети, ни LLM.

**Что мокаем и как:**

- **реализации TTS** — класс `FakeTts extends tts.TTS` прямо в тестах: задаваемые
  `sampleRate`, `capabilities.streaming` и `label`, синтез отдаёт заранее заготовленные
  кадры тишины. Никаких обращений к Mistral и ElevenLabs;
- **LLM** — `voice.testing.FakeLLM`, как в спеке 002;
- **STT и аудиотракт** — не участвуют: язык подаётся в трекер напрямую, разговорные
  тесты идут текстовым прогоном `session.run()`;
- ключи не нужны ни одному тесту; преамбула тестов из спеки 002 продолжает удалять
  секреты из `process.env`.

| Файл | Что проверяет |
|---|---|
| `language.test.ts` | стартовый язык до первой реплики; первая распознанная реплика фиксирует язык немедленно, даже если он не стартовый; совпадающий язык сбрасывает счётчик; переключение ровно на `switchAfter`-й подряд идущей чужой реплике, но не раньше; одна чужая реплика между своими **не** переключает (§4.1 «не переключаться от одного иностранного слова»); `null` не сбрасывает серию; язык вне `enabled` игнорируется полностью; язык вне de/ru/en игнорируется; конструктор падает, если `initial` не входит в `enabled`; `reset()` возвращает в исходное |
| `formatting.test.ts` | время, дата и цена на трёх языках по таблице из 3.4; русская плюрализация для 1/2/5/11/21/101 — именно там наивная реализация ломается; немецкие числительные словами до двенадцати; корректность часового пояса (одна и та же метка времени в `Europe/Berlin` и `UTC` даёт разное локальное время); **полный ICU** — вывод для `ru-RU` содержит кириллицу, а не латиницу |
| `tts-router.test.ts` | роутер объявляет `streaming: true` и заданную частоту; отдаёт реализацию текущего языка и переключается вслед за трекером; нестримящая реализация оборачивается `StreamAdapter`; реализация с другой частотой оборачивается ресемплером, с совпадающей — **не** оборачивается (лишний ресемплер это лишняя задержка); `close()` закрывает все реализации, включая неиспользованные; язык читается в момент начала синтеза, а не в конструкторе |
| `i18n-parity.test.ts` | все три файла парсятся; **наборы ключей совпадают** в de/ru/en; `ai_disclosure` непустой и без `TODO` в каждом языке; нет нераскрытых подстановок `{{…}}`; все три `system.*.md` существуют, непустые и содержат ограничение длины реплики |
| `conversation-multilingual.test.ts` | на `FakeLLM`: приветствие звучит на стартовом языке; после смены языка трекером инструкции агента обновляются на нужный промпт (проверяется через `agent.instructions`); телеметрия смены языка содержит только код языка и **ни одного текстового поля** с репликой |

Чего автотесты не проверяют: качество распознавания языка живой речью, натуральность
голосов, реальную задержку переключения и то, как звучит пересемплированный звук.

### 5.2 Ручное тестирование (выполняет человек)

Требует ключей, микрофона и живого разговора. Оформляется в `manual-tests.md`
по схеме «предусловия → шаги → ожидаемый результат → что записать».

1. **Три языка по отдельности.** Три разговора: начать по-немецки, по-русски, по-английски.
   Ожидание: агент отвечает на языке клиента, голос соответствует языку, реплики
   укладываются в одно-два предложения. Записать субъективную оценку голоса на каждом
   языке — выбор голосов ElevenLabs делается на слух и автотестом не проверяется.
2. **Переключение в середине разговора (§13).** Начать по-немецки, затем перейти на
   русский и говорить на нём. Ожидание: агент переключается, а не отвечает по-немецки.
   Записать, сколько реплик занял переход, и подходит ли значение
   `AGENT_LANGUAGE_SWITCH_AFTER` — это и есть ответ на открытый вопрос 1.
3. **Устойчивость к одному иностранному слову.** В немецкой фразе произнести одно
   английское слово (название блюда, «okay»). Ожидание: агент **не** переключается.
   Это прямое требование §4.1 и самая частая жалоба на многоязычных ботов.
4. **Числа и цены вслух.** Попросить назвать время и цену на каждом языке.
   Ожидание: «neunzehn Uhr dreißig», «девятнадцать тридцать», «half past seven» —
   и цена с правильной валютой. Записать всё, что звучит неестественно: это вход для
   доработки `formatting.ts`.
5. **Смешанная конфигурация роутера.** Если из итерации 3 известно, что у Voxtral есть
   немецкий голос: поставить `TTS_PROVIDER_DE=voxtral`, `TTS_PROVIDER_RU=elevenlabs`,
   `TTS_SAMPLE_RATE=24000` и провести разговор с переключением. Ожидание: оба голоса
   звучат чисто, пересемплированный русский без артефактов и без изменения высоты тона.
   **Это единственная проверка ресемплера, которую нельзя сделать локально** — на слух.
6. **Задержка после переключения.** Снять телеметрию на разговоре со сменой языка.
   Ожидание: переключение не добавляет заметной паузы; `StreamAdapter` на нестримящем
   Voxtral не увеличивает время до первого звука сверх измеренного в итерации 3.
   Записать числа — это вход в пересчёт бюджета §3.3.
7. **Проверка правового текста.** Убедиться, что объявление об ИИ звучит первым на всех
   трёх языках (§13) и что тексты в yaml заполнены владельцем, а не остались заготовками.

## 7. Риски и открытые вопросы

**Риски**

1. **Немецкий голос Voxtral может отсутствовать.** В типизированном списке голосов
   плагина только английские и французские. Если немецкого нет, целевая схема §2.2
   («de|en → Voxtral») неисполнима, и до итерации 14 все три языка остаются на
   ElevenLabs. На архитектуру это не влияет — меняются значения `TTS_PROVIDER_*` — но
   влияет на стоимость и на резидентность данных. Ответ приходит из ручной проверки
   итерации 3.
2. **Пересемплирование добавляет задержку и может дать артефакты.** `AudioResampler` —
   нативный Sox, качество `MEDIUM` по умолчанию. Смягчение: не создавать ресемплер, если
   частоты совпадают, и подобрать `TTS_SAMPLE_RATE` так, чтобы основной языковой поток
   шёл без преобразования. Оценивается только на слух (ручная проверка 5).
3. **`StreamAdapter` поверх нестримящего Voxtral удлиняет паузу перед ответом**: звук
   пойдёт не раньше, чем синтезируется первое предложение. Это уже отмечено как причина
   пересчёта §3.3. Если задержка окажется неприемлемой, вариант — оставить ElevenLabs
   на всех языках до появления Piper.
4. **Утечка дескрипторов ресемплера.** `AudioResampler.close()` обязателен; забытый
   вызов даёт медленную утечку под нагрузкой звонков. Закрывается тестом на `close()`
   роутера и код-ревью.
5. **Порог переключения — компромисс без данных.** Слишком низкий даёт ложные
   переключения на заимствованных словах, слишком высокий — долгие ответы не на том
   языке. Поэтому вынесен в конфиг и проверяется вживую.
6. **Качество определения языка Voxtral на коротких репликах** («Ja», «Да») неизвестно.
   Если на односложных ответах язык скачет, придётся игнорировать реплики короче
   N символов. Не закладываем заранее — сначала измерение (ручная проверка 3).

**Открытые вопросы (не блокируют реализацию)**

1. Точное прочтение §4.1 п.4: переключаться после двух чужих реплик или после трёх.
   Реализовано 2 как значение по умолчанию, вынесено в конфиг; уточняется по итогам
   ручной проверки 2, после чего PROJECT.md правится однозначной формулировкой.
2. Один мультиязычный голос ElevenLabs на все языки или три разных. Три отдельных
   переменных заведены; заполнить можно одинаковыми значениями. Решает владелец на слух.
3. Нужен ли отдельный голос под «женский/мужской» образ ресторана — вопрос бренда,
   не техники.
4. Форматирование числительных для немецкого: словами до двенадцати — эвристика.
   Возможно, для времени всегда лучше цифры («19:30»), а словами только количество
   гостей. Уточняется на ручной проверке 4.
