# Спецификация 002 — Прототип агента на немецком

## 1. Цель и контекст

Вторая половина итерации 3 из docs/PROJECT.md §12. Первая половина — обязательная проверка
стриминга Voxtral Realtime — **выполнена 15.08.2026**: стриминг есть, результат и
ограничения в `docs/architecture.md`. Кастомный STT-плагин не пишем, Deepgram не берём.

Остаётся: локальный прототип агента — **один язык (de), без инструментов**, разговор через
LiveKit, замер фактической задержки и памяти на сессию.

Итерация 3 — контрольная точка проекта, а не проходной этап. Правило §12: *«Не двигайся
дальше, пока диалог на немецком не станет естественным: задержка около секунды, агент не
перебивает на паузах внутри фразы. Все следующие слои только добавят задержку.»* Поэтому
главный результат этой спеки — не код, а **измеренные числа и ощущение разговора**.

Разделы PROJECT.md: §2 и §2.1 (стек и версии), §2.2 (TTS на фазе разработки — ElevenLabs),
§2.3 (плагины, паритет с Python), §3.3 (бюджет задержки), §4.2 (фиксированные фразы в yaml),
§8.1 (замер памяти), §11.1 и §11.3 (объявление об ИИ, запрет записи аудио), §14 (краткость
реплик как главный рычаг стоимости).

Профильный навык — `.claude/skills/voice-testing/SKILL.md`: сценарии A–F, чек-листы по
языкам, обязательные фразы. Для этой итерации применима только часть по немецкому и по
объявлению об ИИ; сценарии с инструментами (A–C, E) проверяются начиная с итерации 6.

## 2. Объём

**Входит:**

1. Рабочий пакет `agent/` — воркер LiveKit Agents на немецком: Voxtral Realtime (STT) +
   Silero (VAD) + Mistral Large (LLM) + ElevenLabs (TTS) + многоязычный turn detector.
2. Конфиг из переменных окружения с валидацией zod; при некорректном конфиге процесс падает.
3. Системный промпт `system.de.md` и фиксированные фразы `i18n/de.yaml` (§4.2).
4. Телеметрия задержки: сбор метрик фреймворка по этапам разговора, **без единого символа
   персональных данных в логах**.
5. `livekit-server` в dev-режиме в `deploy/docker-compose.dev.yml` и скрипт выпуска
   токена для подключения браузера.
6. Автотесты vitest на `voice.testing` с `FakeLLM` — поведение агента проверяется
   локально, без ключей, без сети, без вызовов LLM.
7. Инструкция ручного замера задержки и памяти на сессию.

**Не входит (явно):**

- инструменты агента, n8n, обращения к базе — итерации 5–8. Прототип **ничего не бронирует**;
- второй и третий языки, TTS-роутер, форматирование дат и цен — итерация 4;
- `agent/Dockerfile` и деплой — итерация 12; прототип запускается локально через `pnpm dev`;
- SIP и реальная телефония — итерация 13;
- тестовый звонок из портала — итерация 11;
- Voxtral TTS: на фазе разработки TTS идёт через ElevenLabs (§2.2). Открытый вопрос про
  немецкий голос Voxtral решается в итерации 4, но данные для решения собираются здесь —
  см. ручную проверку 6.

### 3.2 Ключевое требование: запись аудио должна быть выключена явно

**Это самая важная строчка спеки.** При разборе `@livekit/agents` 1.6.4 выяснилось, что
`AgentSession.start()` принимает параметр `record`, а если его не передать, значение
берётся из задания: `if (record === undefined) record = ctx.job.enableRecording`. То есть
запись аудио, транскрипта и трейсов включается **настройкой на стороне LiveKit, а не кодом**,
и по умолчанию `RecordingOptions` включает все категории (`audio`, `traces`, `logs`,
`transcript`).

Для этого проекта это недопустимо: PROJECT.md §11.3 — «Аудио не пишется нигде, egress не
разворачивается вообще», в Германии §201 StGB криминализует запись непубличного устного
слова без согласия; AGENTS.md §6 запрещает добавлять запись аудио и хранение транскриптов.

Требование: **`session.start()` вызывается только с явным `record: false`**. Полагаться на
настройку проекта LiveKit запрещено. Чтобы это не сломали случайно в будущем, опции старта
собираются чистой функцией `buildStartOptions()`, на которую есть автотест (5.1, файл
`session-options.test.ts`).

### 3.3 Конфигурация — `agent/src/config.ts`

```ts
import { z } from 'zod';

export const configSchema = z.object({
  // LiveKit
  LIVEKIT_URL:        z.string().url(),
  LIVEKIT_API_KEY:    z.string().min(1),
  LIVEKIT_API_SECRET: z.string().min(1),

  // Mistral: STT (Voxtral Realtime) и LLM
  MISTRAL_API_KEY: z.string().min(1),
  STT_MODEL: z.string().min(1).default('voxtral-mini-transcribe-realtime-2602'),
  LLM_MODEL: z.string().min(1).default('mistral-large-latest'),

  // ElevenLabs — TTS на фазе разработки (PROJECT.md §2.2)
  ELEVENLABS_API_KEY:  z.string().min(1),
  ELEVENLABS_VOICE_ID: z.string().min(1),
  ELEVENLABS_MODEL:    z.string().min(1),
  ELEVENLABS_BASE_URL: z.string().url().optional(),   // EU-residency эндпоинт

  // Поведение разговора
  AGENT_LANGUAGE:                 z.literal('de').default('de'),
  AGENT_TURN_DETECTOR:            z.enum(['multilingual', 'off']).default('multilingual'),
  AGENT_MIN_ENDPOINTING_DELAY_MS: z.coerce.number().int().min(100).max(2000).default(500),
  AGENT_MAX_ENDPOINTING_DELAY_MS: z.coerce.number().int().min(500).max(10_000).default(3000),

  LOG_LEVEL: z.enum(['debug', 'info', 'warn', 'error']).default('info'),
});

export type Config = z.infer<typeof configSchema>;

/** Падает с читаемым перечнем проблем, а не работает наполовину (PROJECT.md §0.4). */
export function loadConfig(env: NodeJS.ProcessEnv = process.env): Config;
```

Дополнительная проверка внутри `loadConfig`: `AGENT_MIN_ENDPOINTING_DELAY_MS` не больше
`AGENT_MAX_ENDPOINTING_DELAY_MS` — иначе понятная ошибка.

`ELEVENLABS_MODEL` намеренно без значения по умолчанию: конкретное имя
низколатентной мультиязычной модели владелец берёт в своей панели ElevenLabs, а
захардкоженное здесь имя протухнет. В `.env.example` — комментарий с пояснением.

`ELEVENLABS_BASE_URL` — необязательный. EU-residency эндпоинт привязан к тарифу владельца,
его точный адрес берётся из панели ElevenLabs; если переменная не задана, плагин идёт на
свой адрес по умолчанию. На фазе разработки персональных данных нет (§2.2), но переменную
заводим сразу, чтобы перед продом её достаточно было заполнить.

### 3.4 Сборка сессии — `agent/src/session.ts`

Три экспортируемые функции. Разделение на чистые функции сделано ради тестируемости:
без него требование «запись выключена» проверить автотестом невозможно.

```ts
import type { VAD } from '@livekit/agents';
import { voice } from '@livekit/agents';
import type { Config } from './config.ts';

/** Опции AgentSession: модели, VAD, детектор конца реплики, эндпоинтинг. */
export function buildSessionOptions(cfg: Config, vad: VAD): voice.AgentSessionOptions;

/**
 * Опции session.start(). ЕДИНСТВЕННОЕ место, где задаётся record.
 * record: false — требование PROJECT.md §11.3 и AGENTS.md §6, менять нельзя.
 */
export function buildStartOptions(agent: voice.Agent, room: Room): {
  agent: voice.Agent;
  room: Room;
  record: false;
};

/** Немецкий агент прототипа: системный промпт из файла, инструментов нет. */
export function createGermanAgent(systemPrompt: string): voice.Agent;
```

Состав `buildSessionOptions`:

| Компонент | Что берём | Обоснование |
|---|---|---|
| STT | `mistral.STT({ model: cfg.STT_MODEL })` | стриминг подтверждён проверкой; модель обязана содержать `realtime`, иначе плагин бросит исключение |
| VAD | Silero, загружается в `prewarm` | **обязателен**: у Voxtral Realtime нет серверного эндпоинтинга |
| LLM | `mistral.LLM({ model: cfg.LLM_MODEL })` | PROJECT.md §2 |
| TTS | `elevenlabs.TTS({ voiceId, model, baseURL? })` | §2.2, конфигурация фазы разработки |
| turn detector | `MultilingualModel` из `@livekit/agents-plugin-livekit`, если `AGENT_TURN_DETECTOR !== 'off'` | §12: агент не должен перебивать на паузах внутри фразы |
| endpointing | `{ mode: 'fixed', minDelay, maxDelay }` из конфига | §3.3: порог тишины 300–550 мс; значение подбирается вживую |

Переключатель `AGENT_TURN_DETECTOR=off` нужен не «на будущее», а для ручной проверки:
владелец сравнивает разговор с детектором и без него и выбирает по ощущению — это прямая
задача итерации по §12. Заодно это готовый рычаг для CPX22 (§8.2 упоминает отключённый
turn detector как меру экономии).

⚠️ Модель turn detector — многоязычная (`livekit/turn-detector`, ревизия `v0.4.1-intl`),
скачивается с HuggingFace командой `download-files` и работает локально через onnxruntime.
Список поддерживаемых языков лежит в `languages.json` внутри модели и резолвится в рантайме
с откатом на базовый язык. **Наличие немецкого в списке подтверждается при первом запуске** —
внесено в ручные проверки.

### 3.5 Точка входа — `agent/src/index.ts`

```ts
import { cli, defineAgent, voice, WorkerOptions } from '@livekit/agents';
import * as silero from '@livekit/agents-plugin-silero';
import { fileURLToPath } from 'node:url';

export default defineAgent({
  // Silero грузится один раз на процесс, а не на каждый звонок
  prewarm: async (proc) => {
    proc.userData.vad = await silero.VAD.load();
  },

  entry: async (ctx) => {
    const cfg = loadConfig();
    const vad = ctx.proc.userData.vad as VAD;

    const session = new voice.AgentSession(buildSessionOptions(cfg, vad));
    attachTelemetry(session, ctx);                       // см. 3.6

    const agent = createGermanAgent(await loadSystemPrompt('de'));
    await session.start(buildStartOptions(agent, ctx.room));   // record: false

    // §11.1: объявление об ИИ звучит ПЕРВЫМ, до сбора любых данных.
    // Текст фиксированный из yaml, не генерируется LLM (§4.2).
    const phrases = await loadPhrases('de');
    session.say(`${phrases.greeting} ${phrases.ai_disclosure}`);
  },
});

cli.runApp(new WorkerOptions({ agent: fileURLToPath(import.meta.url) }));
```

`WorkerOptions` берёт `wsURL`, `apiKey`, `apiSecret` из окружения; передавать их явно не
нужно, но `loadConfig()` всё равно проверяет их наличие — чтобы падать сразу и понятно,
а не на первом входящем звонке.

CLI фреймворка даёт подкоманды `dev`, `start`, `connect --room <name>`, `console`,
`download-files`. Для разработки используется `dev`; `download-files` нужен один раз,
чтобы скачать модель turn detector.

### 3.6 Телеметрия — `agent/src/telemetry.ts`

Задача: получить числа для §3.3 и §13, не нарушив §0.4 («персональные данные не
логируются: ни имён, ни телефонов, ни транскриптов»).

Фреймворк отдаёт метрики событием `MetricsCollected`. Нужные поля (имена сверены с
`@livekit/agents` 1.6.4):

| Тип метрики | Поле | Смысл |
|---|---|---|
| `EOUMetrics` | `endOfUtteranceDelayMs` | сколько ждали после того, как клиент замолчал |
| `EOUMetrics` | `transcriptionDelayMs` | задержка финализации транскрипта |
| `LLMMetrics` | `ttftMs` | до первого токена ответа |
| `TTSMetrics` | `ttfbMs` | до первого аудиочанка |

```ts
export interface TurnLatency {
  endOfUtteranceDelayMs: number;
  transcriptionDelayMs: number;
  llmTtftMs: number;
  ttsTtfbMs: number;
  /** Сумма — то, что клиент воспринимает как паузу перед ответом. */
  totalMs: number;
}

/** Чистая функция: из набора метрик одного хода собирает срез задержки. */
export function summarizeTurn(metrics: AgentMetrics[]): TurnLatency | null;

/** Сводка за сессию: p50 и максимум по каждому этапу + число ходов. */
export function summarizeSession(turns: TurnLatency[]): SessionLatencySummary;

/** Подписка на сессию: пишет только числа. Никакого текста реплик. */
export function attachTelemetry(session: voice.AgentSession, ctx: JobContext): void;
```

Правила логирования, обязательные к соблюдению:

- логируются **только числа и счётчики**; ни `UserInputTranscribedEvent.transcript`,
  ни содержимое `ConversationItemAdded` в лог не попадают;
- уровень логирования по умолчанию `info`; `debug` фреймворка выводит транскрипты, поэтому
  в `.env.example` рядом с `LOG_LEVEL` стоит предупреждение, что `debug` включают только
  на своих тестах и никогда — при реальных звонках;
- в конце сессии — одна строка со сводкой и с `process.memoryUsage().rss` процесса сессии
  (это и есть замер памяти, см. 3.8).

### 3.7 Промпт и фразы

`agent/src/prompts/system.de.md` — системный промпт на немецком. Обязательные требования
в тексте промпта:

- роль: сотрудник ресторана, отвечающий на звонок;
- **одна–две коротких фразы на реплику, без повторения уже сказанного** (§14 — главный
  рычаг стоимости и одновременно приятности разговора; §13 проверяет это отдельным пунктом);
- **ничего не выдумывать**: ни блюд, ни цен, ни свободных столиков. Инструментов пока нет,
  поэтому на просьбу забронировать агент честно отвечает, что эта функция ещё не
  подключена, и предлагает перезвонить позже;
- не переходить на другие языки — прототип одноязычный;
- никаких обещаний от имени ресторана.

`agent/src/i18n/de.yaml` — только те ключи, которые реально используются:

```yaml
greeting: "Guten Tag, hier ist das Restaurant …"
ai_disclosure: "…"      # §11.1, обязательно, не пустое
goodbye: "…"
error_unavailable: "…"  # аварийная фраза, если модель недоступна
```

Юридический текст объявления об ИИ пишет владелец — это фраза с правовым значением, и
подставлять сюда выдуманный текст нельзя. В файле остаётся заготовка с комментарием
и пометкой, что перед любым реальным звонком её обязан заполнить владелец; автотест
проверяет, что значение непустое и что в нём нет плейсхолдера `TODO`.

### 3.8 Замер памяти — правка PROJECT.md §8.1

PROJECT.md §8.1 требует замерить память «через `docker stats` под тремя параллельными
звонками». В итерации 3 это невыполнимо буквально: контейнера у агента ещё нет, его
`Dockerfile` появляется в итерации 12, а прототип запускается локально.

Решение: в этой итерации память меряется **изнутри процесса сессии** —
`process.memoryUsage().rss` в строке-сводке при завершении сессии. Фреймворк запускает
каждый звонок отдельным дочерним процессом, поэтому это и есть искомая величина «RAM на
сессию». Замер под тремя параллельными звонками через `docker stats` переносится в
итерацию 12, когда агент поедет в контейнере. PROJECT.md §8.1 правится соответственно;
правка отмечена в `docs/architecture.md`.

### 3.9 Локальное окружение

`deploy/docker-compose.dev.yml` — добавляется сервис:

```yaml
  livekit:
    image: livekit/livekit-server:v1.13.5   # точный тег Codex сверяет на дату работы
    command: --dev --bind 0.0.0.0
    ports:
      - "7880:7880"
      - "7881:7881"
      - "50000-50100:50000-50100/udp"
```

Режим `--dev` поднимает сервер с известными ключами `devkey` / `secret` — это только для
локальной разработки, в бой такой конфиг не идёт (итерация 12).

`scripts/dev-token.ts` — печатает join-токен и готовый URL, чтобы владелец мог подключиться
браузером: на вход имя комнаты и identity, на выходе токен, подписанный `livekit-server-sdk`.

## 5. Тестирование

### 5.1 Автотесты (vitest, только локальное окружение)

Ограничение AGENTS.md §4 здесь особенно жёсткое: агент по своей природе состоит из вызовов
внешних API. Тем не менее содержательные тесты возможны — `@livekit/agents` 1.6.4 поставляет
модуль `voice.testing` с `FakeLLM` и текстовым прогоном `session.run({ userInput })`.
Это позволяет проверять **поведение агента** без ключей, без сети и без единого вызова LLM.

**Что мокаем и как:**

- LLM → `voice.testing.FakeLLM` с заранее заданными парами вход→ответ;
- STT и TTS → **не участвуют вообще**: `session.run()` работает в текстовом режиме,
  аудиотракт не поднимается;
- LiveKit-комната → не нужна, сессия запускается без `room`;
- ключи → тесты не читают `.env` и не требуют переменных; конфиг собирается из литерального
  объекта с фиктивными значениями (`LIVEKIT_API_KEY: 'test-key'` и т. п.).

Дополнительно, по образцу спеки 001, глобальная преамбула тестов **удаляет** из
`process.env` ключи `MISTRAL_API_KEY`, `ELEVENLABS_API_KEY`, `LIVEKIT_API_SECRET`,
`LIVEKIT_API_KEY`, `N8N_WEBHOOK_SECRET`, `TELEGRAM_BOT_TOKEN` — если владелец
экспортировал их в оболочке, до тестов они не доберутся, и случайный реальный вызов
невозможен физически.

| Файл | Что проверяет |
|---|---|
| `config.test.ts` | валидный набор переменных разбирается; отсутствие обязательного ключа даёт ошибку с перечнем недостающих полей; `min > max` для эндпоинтинга отвергается; значения по умолчанию проставляются; `AGENT_LANGUAGE` кроме `de` не принимается |
| `i18n.test.ts` | `de.yaml` парсится; присутствуют все четыре ключа; `ai_disclosure` непустой и не содержит `TODO` (§11.1 — пустое объявление об ИИ недопустимо); фразы не содержат подстановок вида `{{…}}`, которые прототип не умеет раскрывать |
| `prompt.test.ts` | `system.de.md` загружается, непустой, содержит явное ограничение длины реплики (§14) и запрет выдумывать позиции меню (§13) |
| `session-options.test.ts` | **`buildStartOptions()` возвращает `record: false`** — страж требования §11.3, самый важный тест итерации; `buildSessionOptions()` переносит `minDelay`/`maxDelay` из конфига в опции эндпоинтинга; при `AGENT_TURN_DETECTOR='off'` детектор в опциях отсутствует, при `'multilingual'` — присутствует |
| `conversation.test.ts` | на `FakeLLM`: агент отвечает на реплику клиента (`result.expect.nextEvent().isMessage({ role: 'assistant' })`); в контексте сессии присутствует системный промпт; агент не порождает вызовов инструментов — их нет вовсе |
| `telemetry.test.ts` | `summarizeTurn()` складывает четыре этапа в `totalMs` на синтетических метриках; отсутствие части метрик даёт `null`, а не NaN; `summarizeSession()` считает p50 и максимум; **в возвращаемой структуре нет ни одного строкового поля** — машинная гарантия того, что транскрипт не утечёт в лог |

Чего автотесты принципиально **не** проверяют: качество распознавания, натуральность речи,
фактическую задержку, поведение при обрыве сети, потребление памяти. Всё это — раздел 5.2.

### 5.2 Ручное тестирование (выполняет человек)

Требует реальных ключей Mistral и ElevenLabs, работающего микрофона и живого разговора,
поэтому выполняется владельцем. Оформляется Codex в `manual-tests.md` по схеме
«предусловия → шаги → ожидаемый результат → что записать».

1. **Первый запуск и загрузка модели.** `pnpm db:up` не нужен; поднять `livekit` из
   dev-compose, выполнить `download-files` (скачивание модели turn detector), запустить
   агента в режиме `dev`. Ожидание: воркер регистрируется, ошибок нет. Записать: версию
   модели turn detector и **есть ли немецкий в её `languages.json`** — этого нельзя узнать
   заранее, список лежит внутри скачиваемой модели.
2. **Разговор на немецком.** Подключиться браузером (токен из `scripts/dev-token.ts`),
   поздороваться. Ожидание: первым звучит приветствие с объявлением об ИИ, дальше
   осмысленный диалог; реплики агента укладываются в одно-два предложения.
   Записать: субъективную оценку и явные проблемы.
3. **Задержка.** Провести не менее десяти ходов, снять сводку телеметрии.
   Ожидание по §3.3 и §13: **меньше 1,5 с без инструментов**. Записать p50 и максимум по
   каждому этапу отдельно (`endOfUtteranceDelayMs`, `transcriptionDelayMs`, `llmTtftMs`,
   `ttsTtfbMs`) — по этим числам в итерации 4 пересчитывается бюджет §3.3.
4. **Паузы внутри фразы.** Произнести фразу с паузой в середине («Ich hätte gerne …
   …einen Tisch»). Ожидание: агент **не перебивает**. Прогнать дважды —
   с `AGENT_TURN_DETECTOR=multilingual` и с `off`, сравнить. При необходимости подобрать
   `AGENT_MIN_ENDPOINTING_DELAY_MS` в диапазоне 300–550 мс (§3.3) и записать выбранное
   значение — оно станет значением по умолчанию.
5. **Память на сессию.** Провести три параллельных разговора (три вкладки браузера,
   три комнаты) и снять `rss` каждого процесса сессии из строки-сводки.
   Ожидание по §8.1 — 150–250 МБ на сессию. Записать фактические числа: PROJECT.md §8.1
   требует заменить оценочные значения измеренными, а от них считается вместимость сервера.
6. **Проверка запрета записи.** После разговоров убедиться, что на диске не появилось
   аудиофайлов (`*.ogg`) ни в рабочем каталоге, ни во временном, и что в логах нет текста
   реплик. Это ручная проверка §11.3 и §0.4: автотест ловит `record: false` в опциях, но
   подтвердить отсутствие файлов на диске может только человек после реального звонка.
7. **Немецкий голос Voxtral TTS — сбор данных для итерации 4.** Пока ключ Mistral под
   рукой: проверить по документации Mistral и одним запросом, существует ли немецкий голос
   Voxtral TTS. Это не входит в объём итерации 3, но ответ определяет схему TTS-роутера в
   итерации 4 (открытый вопрос в `docs/architecture.md`). Записать ответ туда же.
8. **Поведение при недоступности модели.** Подставить заведомо неверный `MISTRAL_API_KEY`
   и позвонить. Ожидание: агент произносит аварийную фразу из `de.yaml`, а не молчит и не
   обрывает звонок (§13). Полноценный сценарий с переводом в обратный звонок появится в
   итерации 8 — здесь проверяется только то, что тишины не возникает.

## 7. Риски и открытые вопросы

**Риски**

1. **Запись аудио включается вне кода.** Главный риск итерации и причина, по которой
   `record: false` вынесен в отдельную функцию с тестом. Если в будущем кто-то вызовет
   `session.start()` напрямую, запись включится настройкой проекта LiveKit молча.
   Смягчение: тест-страж + пункт в ручных проверках + запись в `docs/architecture.md`.
2. **Немецкий в модели turn detector не подтверждён.** Список языков лежит внутри
   скачиваемой модели. Если немецкого нет — детектор отключается
   (`AGENT_TURN_DETECTOR=off`), и качество пауз обеспечивается подбором
   `minDelay`; это не блокирует итерацию, но ухудшает ощущение разговора.
3. **Задержка может не уложиться в 1,5 с.** Известный вклад: ElevenLabs вместо Voxtral,
   отсутствие настройки `targetStreamingDelayMs` (недоступна из Node-плагина) и
   несжимаемый порог тишины VAD. Если норматив не выполняется, итерация 4 обязана начаться
   с оптимизации, а не с мультиязычности — это прямое требование §12.
4. **Подключение браузера к локальному LiveKit.** Хостинговый LiveKit Agents Playground
   обращается к `ws://localhost:7880`; браузеры считают localhost доверенным источником,
   поэтому это должно работать, но зависит от браузера и его настроек. Запасной путь —
   LiveKit CLI. Проверяется первым же ручным тестом.
5. **TypeScript 7.** Актуальная версия — мажорный скачок с новым компилятором. Обновление
   не обязано пройти гладко; спека разрешает остаться на 5.x с записью причины.
6. **Спека 001 не верифицирована.** Если при первом реальном `pnpm install` и запуске
   тестов базы выяснится, что там есть ошибки, это всплывёт именно на шаге 1 этой итерации.
   Чинить их следует отдельной задачей, а не внутри этой спеки.

**Открытые вопросы (не блокируют реализацию)**

1. Имя модели Mistral для «Large 3». В union плагина есть `mistral-large-latest` и
   датированные `mistral-large-2512` / `2411`. Прототип берёт `latest`; фиксацию точной
   даты сделать в итерации 4, когда появятся evals.
2. Низколатентная модель ElevenLabs и конкретный немецкий голос — выбирает владелец в своей
   панели; спека намеренно не хардкодит имена, которые протухают.
3. Точный адрес EU-residency эндпоинта ElevenLabs зависит от тарифа. На фазе разработки
   персональных данных нет, поэтому это не блокер, но перед первым боевым рестораном
   переменная обязана быть заполнена (§2.2).
4. Стоит ли уже здесь ограничивать `jobMemoryLimitMB` в `WorkerOptions`. Ограничение есть
   во фреймворке и пригодится на сервере (§8.2.1), но осмысленное значение можно выбрать
   только после замера памяти — то есть по итогам этой же итерации.
