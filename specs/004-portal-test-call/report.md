# Отчёт о реализации спеки 004

Дата: 16.08.2026
Исполнитель: Claude Code (по явной просьбе владельца «реализуй»; обычно этот этап у Codex)
Среда: Windows 11, Node.js 24, pnpm 11.21.0, Next.js 16.3.1

Статус спеки — `implemented`. `verified` ставится после живого звонка владельцем по
`manual-tests.md`: реальные ключи, микрофон и внешняя сеть автотестам запрещены.

## Что сделано

- Каркас `portal/` на Next.js 16.3.1 (App Router, Turbopack), `strict` со всеми строгостями
  из `tsconfig.base.json`, включая `exactOptionalPropertyTypes` и `noUncheckedIndexedAccess`.
- Вход по §7.1: bcrypt cost 12 (`bcryptjs`), подписанная httpOnly-cookie на `jose`
  (HS256, 8 часов, `SameSite=Strict`), rate limit 5 попыток на IP за 15 минут,
  `pnpm portal:hash` со скрытым вводом пароля.
- Разграничение доступа по §7.2 в два слоя: `proxy.ts` закрывает все маршруты, а серверные
  обработчики независимо зовут `guardRequest`. Тестовый звонок доступен обеим ролям
  одинаково — как решил владелец.
- Оболочка с шапкой (логин, бейдж роли, «Выйти») и меню из одного пункта.
- `/test-call`: выпуск токена LiveKit на разовую комнату, подключение через
  `livekit-client`, микрофон, воспроизведение голоса агента, живой транскрипт топиком
  `lk.transcription` с разделением реплик гостя и агента.
- 32 автотеста в проекте `portal`, без сети, ключей и LLM.
- Документы: `portal/README.md`, разделы в корневом `README.md`, `.env.example`,
  журнал решений и таблица версий в `docs/architecture.md`, отметки в `docs/PROJECT.md` §12.

## Отклонения от спеки и почему

1. **`middleware.ts` → `proxy.ts`.** Next 16 объявил конвенцию `middleware` устаревшей.
   Существеннее переименования: route segment config в этом файле запрещён вовсе, поэтому
   планировавшийся `export const config = { runtime: 'nodejs' }` валит сборку. Proxy и так
   всегда исполняется в Node-рантайме, так что цель достигнута — просто иначе.
2. **Корневой `.env` подгружается из `next.config.ts`, а не через `NODE_OPTIONS`.** Приём
   агента (`node --env-file-if-exists=../.env … next build`) роняет сборку: Node запрещает
   этот флаг воркерам (`ERR_WORKER_INVALID_EXEC_ARGV`). Использован
   `process.loadEnvFile()` — конфиг исполняется в каждом процессе Next.
3. **`lib/auth.ts` разделён на `lib/session.ts` и `lib/users.ts`.** Работа с подписью не
   должна тянуть за собой `bcryptjs`: `proxy.ts` импортирует только проверку сессии.
4. **jose зафиксирована на 6.2.8, а не 6.2.9.** Свежая версия опубликована 15.08.2026 и не
   проходит репозиторный карантин `minimumReleaseAge: 1440`.
5. **`biome.json` научен читать `.gitignore`.** После первой сборки портала `biome check .`
   уходил в 42 тысячи диагностик по содержимому `.next/`.
6. **Добавлен `login-route.test.ts`**, которого в плане не было: 429 и выдача cookie —
   ровно те места, которые проверяются в приёмке §13, и они дёшево тестируются локально.
7. **`portal/AGENTS.md` и `portal/CLAUDE.md` коммитятся.** Их создаёт сам `next dev`
   (`node_modules/next/dist/server/lib/generate-agent-files.js`) и восстанавливает при
   каждом запуске, поэтому не коммитить их — значит держать вечно грязное дерево. Сверху
   добавлена ссылка на корневой `AGENTS.md`, чтобы вложенный файл не подменял правила
   проекта; генератор трогает только содержимое между своими маркерами.

## Как запускать

```powershell
pnpm portal:hash   # завести пароли, вставить хеши в .env
pnpm livekit:up
pnpm agent:dev
pnpm portal:dev    # http://localhost:3000
```

Открывать строго `http://localhost:3000`: микрофон браузер отдаёт только в защищённом
контексте.

## Что этот прогон закроет для проекта

Живой звонок по `manual-tests.md` — первый запуск агента вживую вообще. Он даёт три вещи
сразу: приёмку ощущения разговора из итерации 3, фактическую задержку для §3.3 и RSS сессии
для §8.1. Числа переносятся в `docs/architecture.md`.

## Известные ограничения

- **Разговор только по-немецки:** агент одноязычный by design, мультиязычность — спека 003.
- **Rate limit живёт в памяти процесса:** при нескольких репликах нужно общее хранилище.
- **`LOG_LEVEL=warn` обязателен для живого звонка:** дефект логирования реплик в
  LiveKit Agents 1.6.4 не устранён, а обойдён. Статус спеки 002 не меняется.
- **Язык интерфейса портала — русский**, вопрос немецкой локализации для персонала внесён
  в PROJECT.md §7 и решается в итерации 10.
