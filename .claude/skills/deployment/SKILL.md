# Деплой и инфраструктура

Топология контейнеров — docs/PROJECT.md §3.1, ресурсы и лимиты — §8, порты и фаервол — §8.3.

## Порядок деплоя

1. Бэкап Postgres ДО любых изменений (`deploy/backup.sh`).
2. Применение миграций; проверка списка применённых версий.
3. Порядок поднятия: postgres → n8n → livekit → livekit-sip → agent → portal → caddy.
4. Health-check каждого контейнера после старта; не идти дальше, пока предыдущий не здоров.
5. Смоук-тест: тестовый звонок из портала.

## Откат

Для каждого изменения заранее известен путь отката: предыдущий образ + откат миграции.
После любого изменения схемы БД — обязательная проверка, что бэкап снимается и реально
восстанавливается.

## Правила инфраструктуры

- Лимиты памяти прописаны для всех контейнеров (PROJECT.md §8.2.1), swap 2 ГБ,
  `restart: unless-stopped` на всех сервисах.
- Наружу открыты только порты из §8.3. `postgres`, `n8n`, `piper`, `portal` — только
  внутри Docker-сети; n8n через Caddy и только с IP владельца (открытый n8n = готовый RCE).
- Секреты — только в env на сервере; не в репозитории, не в образах, не в логах.
- Аудио и транскрипты не сохраняются нигде; egress не разворачивается вообще.
- Версии образов фиксируются точно; изменение версии — через `docs/architecture.md`.
- На shared-ядрах мониторить steal time; регулярно > 5% — план переезда на AX41.
