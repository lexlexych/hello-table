# Инструменты агента

Список инструментов и их вебхуков — docs/PROJECT.md §6. Каждый инструмент — вебхук n8n;
агент не имеет прямого доступа к Postgres.

## Порядок — строго такой, не перескакивать

1. **Контракт** в `docs/tool-contracts.md`: назначение, вход, выход, ошибки. Ответ
   вебхука — строго типизированная JSON-структура, никакого свободного текста: агент
   передаёт результат в LLM, и непредсказуемый формат заставит модель выдумывать.
2. **Zod-схема** в `packages/contracts/src/tools.ts` — единственный источник типов.
   Дублировать типы в агенте или портале запрещено.
3. **Workflow n8n** (по навыку n8n-workflows), экспорт JSON в `n8n/workflows/`.
4. **Регистрация в агенте** (`agent/src/tools/`): через общий HTTP-клиент к n8n с
   HMAC-подписью (`X-Signature` = HMAC-SHA256 тела, секрет `N8N_WEBHOOK_SECRET`);
   каждый запрос несёт `restaurant_id` и `session_id`.

## Обязательные требования к каждому инструменту

- **Филлер-фраза перед вызовом** на языке разговора («Einen Moment, ich schaue nach» /
  «Секунду, проверяю» / «One moment, let me check»). Реализуется хуком перед вызовом
  инструмента, а не промптом — LLM забудет это делать. Фразы — из `agent/src/i18n/`.
- **Таймаут и обработка ошибок вебхука.** При таймауте или ошибке агент произносит
  внятное извинение на языке разговора и предлагает обратный звонок; молчаливое
  зависание запрещено.
- **Валидация ответа** zod-схемой на стороне агента до передачи результата в LLM.
- **Тест (vitest)** на каждый инструмент: happy path + таймаут + невалидный ответ.
  n8n в тестах мокается; реальные сетевые вызовы, API-ключи и LLM запрещены.
