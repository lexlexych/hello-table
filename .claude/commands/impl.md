Ты выполняешь этап РЕАЛИЗАЦИИ двухэтапного процесса (AGENTS.md §3). Код пишет Codex;
твоя роль — оркестратор и приёмка. Сам код приложения не пиши.

Спека: $ARGUMENTS

1. Найди спеку: по номеру из аргумента, либо (если аргумент пуст) последнюю в specs/ со
   статусом ready-for-impl. Если такой нет — остановись и сообщи, что сначала нужен /spec.
2. Прочитай спеку целиком. Поменяй её статус на in-progress.
3. Передай реализацию Codex. Используй плагин codex (Skill codex:rescue либо агент
   codex:codex-rescue); если плагин недоступен — запусти Codex CLI напрямую через
   `codex exec` в корне репозитория. Задание для Codex обязано требовать:
   - сначала прочитать AGENTS.md, затем specs/NNN-<slug>/spec.md полностью;
   - перед работой в профильной области прочитать соответствующий
     .claude/skills/<область>/SKILL.md (список — AGENTS.md §7);
   - реализовать строго по спеке; отклонения — только при неисполнимости спеки,
     с фиксацией и обоснованием в report.md;
   - написать автотесты (vitest) только для локально проверяемого: БЕЗ реальных
     API-ключей, БЕЗ реальных сетевых вызовов внешних API (Mistral, ElevenLabs,
     LiveKit, Telegram и др.), БЕЗ вызовов LLM; внешние сервисы мокать;
   - для непокрываемого автотестами написать specs/NNN-<slug>/manual-tests.md —
     пошаговую инструкцию для человека (предусловия → шаги → ожидаемый результат);
   - написать specs/NNN-<slug>/report.md: что сделано, отклонения, как запускать,
     результат прогона тестов.
4. После завершения Codex выполни приёмку сам:
   - сверь результат с критериями приёмки из спеки;
   - прогони тесты локально; убедись, что они проходят и не делают сетевых вызовов;
   - проверь, что report.md и (если нужен) manual-tests.md существуют и содержательны.
5. Если приёмка не пройдена — верни задачу Codex тем же способом с конкретным списком
   замечаний и повтори приёмку.
6. По успеху: статус спеки → implemented; отметь итерацию в docs/PROJECT.md §12, если она
   закрыта целиком; покажи владельцу резюме: что сделано, результаты тестов и список
   ручных проверок из manual-tests.md, которые он должен выполнить сам.
